### Root Cause

In [`ConsolidatedMetadata._flat_to_nested`](file:///subject/src/zarr/core/group.py#L211-L285), child keys were grouped by parent path using `itertools.groupby`:

```python
keys = sorted(metadata, key=lambda k: k.count("/"))
grouped = {
    k: list(v) for k, v in itertools.groupby(keys, key=lambda k: k.rsplit("/", 1)[0])
}
```

`itertools.groupby` only groups *consecutive* elements matching the key function (`k.rsplit("/", 1)[0]`). Because `keys` was sorted only by depth (`k.count("/")`) rather than by parent path, keys belonging to the same parent that were not contiguous produced multiple separate groups. Evaluating the dict comprehension `{k: list(v) for k, v in itertools.groupby(...)}` caused later groups for a parent key to overwrite earlier ones, silently dropping all child keys from earlier groups.

Dropped child nodes were never moved into their parent's consolidated metadata and remained as stray slash-containing keys at the top level of the metadata dictionary. Sibling groups differing only by case were especially prone to this because [`to_dict`](file:///subject/src/zarr/core/group.py#L151-L165) serializes keys ordered by casefolded names, which interleaves the children of case-variant siblings.

### Fix

Replaced `itertools.groupby` in [`_flat_to_nested`](file:///subject/src/zarr/core/group.py#L240-L245) with `defaultdict(list)`:

```python
keys = sorted(metadata, key=lambda k: k.count("/"))
grouped: dict[str, list[str]] = defaultdict(list)
for k in keys:
    grouped[k.rsplit("/", 1)[0]].append(k)
```

Because `keys` is sorted in ascending order of depth (`k.count("/")`), parent keys are naturally inserted into `grouped` in top-down order (depth 0, depth 1, etc.) while all children sharing a parent are accumulated without dropping any elements regardless of input key order.
